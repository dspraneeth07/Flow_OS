In general, environment variables, like `FLOWOS_PORT` or `FLOWOS_LOG_LEVEL`, configure how FlowOS runs.
These are broad settings that apply to your entire FlowOS deployment.

In contrast, global variables are user-defined values stored in FlowOS's database for use in flows, such as `OPENAI_API_KEY`.
FlowOS can also source global variables from environment variables.
For more information, see [FlowOS global variables](/configuration-global-variables).

## Configure environment variables for FlowOS OSS

FlowOS recognizes [supported environment variables](#supported-variables) from the following sources:

- Environment variables set in your terminal.
- Environment variables imported from a `.env` file when starting FlowOS.
- Environment variables set with the [FlowOS CLI](./configuration-cli), including the `--env-file` option and direct options, such as `--port`.

You can choose to use one or more of these sources.

### Precedence {#precedence}

If the same environment variable is set in multiple places, the following hierarchy applies:

1. FlowOS CLI options override all other sources.
2. The `.env` file overrides system environment variables.
3. System environment variables are used only if not set elsewhere.
When running a FlowOS Docker image, the `-e` flag can be used to set additional system environment variables.

For example:

* If you set `FLOWOS_PORT=8080` in your system environment and `FLOWOS_PORT=7860` in `.env`, FlowOS uses `7860` from `.env`.
* If you use the FlowOS CLI to run `flowos run --env-file .env --port 9000`, and you set `FLOWOS_PORT=7860` in `.env`, then FlowOS uses `9000` from the CLI option.

### Set environment variables in your terminal {#configure-variables-terminal}

Run the following commands to set environment variables for your current terminal session:

<Tabs>
<TabItem value="linux-macos" label="Linux or macOS" default>

```bash
export VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="windows" label="Windows">

```
set VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="docker" label="Docker">

```bash
docker run -it --rm \
    -p 7860:7860 \
    -e VARIABLE_NAME='VALUE' \
    flowosai/flowos:latest
```

</TabItem>
</Tabs>

When you start FlowOS, it looks for environment variables that you've set in your terminal.
If it detects a supported environment variable, then it automatically adopts the specified value, subject to [precedence rules](#precedence).

### Import environment variables from a .env file {#configure-variables-env-file}

1. If FlowOS is running, quit FlowOS.

2. Create a `.env` file, and then open it in your preferred editor.

3. Define [FlowOS environment variables](#supported-variables) in the `.env` file.

    <details>
    <summary>Example: .env</summary>

    ```text
    DO_NOT_TRACK=True
    FLOWOS_AUTO_LOGIN=False
    FLOWOS_AUTO_SAVING=True
    FLOWOS_AUTO_SAVING_INTERVAL=1000
    FLOWOS_BACKEND_ONLY=False
    FLOWOS_BUNDLE_URLS=["https://github.com/user/repo/commit/hash"]
    FLOWOS_CACHE_TYPE=async
    FLOWOS_COMPONENTS_PATH=/path/to/components/
    FLOWOS_COMPONENTS_INDEX_PATH=/path/to/component_index.json
    FLOWOS_CONFIG_DIR=/path/to/config/
    FLOWOS_DATABASE_URL=postgresql://user:password@localhost:5432/flowos
    FLOWOS_DEV=False
    FLOWOS_FALLBACK_TO_ENV_VAR=False
    FLOWOS_HEALTH_CHECK_MAX_RETRIES=5
    FLOWOS_HOST=localhost
    FLOWOS_LANGCHAIN_CACHE=InMemoryCache
    FLOWOS_MAX_FILE_SIZE_UPLOAD=10000
    FLOWOS_MAX_ITEMS_LENGTH=100
    FLOWOS_MAX_TEXT_LENGTH=1000
    FLOWOS_LOG_LEVEL=error
    FLOWOS_OPEN_BROWSER=False
    FLOWOS_PORT=7860
    FLOWOS_REMOVE_API_KEYS=False
    FLOWOS_SAVE_DB_IN_CONFIG_DIR=True
    FLOWOS_SECRET_KEY=somesecretkey
    FLOWOS_STORE_ENVIRONMENT_VARIABLES=True
    FLOWOS_SUPERUSER=adminuser
    FLOWOS_SUPERUSER_PASSWORD=adminpass
    FLOWOS_WORKER_TIMEOUT=300
    FLOWOS_WORKERS=3
    ```

    For additional examples, see [`.env.example`](https://github.com/flowos-ai/flowos/blob/main/.env.example) in the FlowOS repository.

    </details>

4. Save and close `.env`.

5. Start FlowOS with your `.env` file:

    <Tabs>
    <TabItem value="local" label="Local" default>

    ```bash
    uv run flowos run --env-file .env
    ```

    </TabItem>
    <TabItem value="docker" label="Docker">

    ```bash
    docker run -it --rm \
        -p 7860:7860 \
        --env-file .env \
        flowosai/flowos:latest
    ```

    </TabItem>
    </Tabs>

    If your `.env` file isn't in the same directory, provide the path to your `.env` file.

On startup, FlowOS imports the environment variables from your `.env` file, as well as any others that you set in your terminal, and then adopts their specified values.

## Set environment variables for FlowOS Desktop

Environment variables set in your terminal aren't automatically available to GUI-based applications like FlowOS Desktop when you launch them from the Windows or macOS GUI.

To modify environment variables for FlowOS Desktop, set environment variables in a Desktop `.env` file, and then restart the app.

<Tabs>
<TabItem value="macos" label="macOS" default>

To modify the macOS `.env` file, do the following:

1. Create or edit `~/.flowos/data/.env`.
2. Add your FlowOS environment variables, for example:

    ```text
    FLOWOS_LOG_LEVEL=info
    FLOWOS_DOCLING=true
    ```

3. Save the file.
4. Restart FlowOS Desktop.

</TabItem>
<TabItem value="windows" label="Windows .env file">

To modify the Windows `.env` file, do the following:

1. Create or edit `%APPDATA%\com.FlowOSDesktop\data\.env`.
2. Add your FlowOS environment variables, for example:

    ```text
    FLOWOS_LOG_LEVEL=info
    FLOWOS_DOCLING=true
    ```

3. Save the file.
4. Restart FlowOS Desktop.

</TabItem>
<TabItem value="windows-user-vars" label="Windows user environment variables">

Windows supports two sources for FlowOS Desktop environment variables: a FlowOS application `.env` file, and Windows user environment variables.

The `.env` file at `%APPDATA%\com.FlowOSDesktop\data\.env` is the recommended approach, but
Windows user variables are useful for single-sourcing API keys between FlowOS and other Windows applications.
If the same variable is defined in both the FlowOS application `.env` file and as a Windows user environment variable, the `.env` file takes precedence.

To modify the Windows user environment variables, do the following:

1. Press <kbd>Win + R</kbd>, enter `sysdm.cpl`, and then press <kbd>Enter</kbd>.
2. Click the **Advanced** tab, and then click **Environment Variables**.
3. In **User variables**, click **New**.
4. Enter the variable name, such as `OPENAI_API_KEY`, and its value.
5. Click **OK**, and then **restart FlowOS Desktop**.

</TabItem>
</Tabs>

### Server

The following environment variables set base FlowOS server configuration, such as where the server is hosted, required files for SSL encryption, and the deployment type (frontend and backend, backend-only, development mode).

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `FLOWOS_HOST` | String | `localhost` | The host on which the FlowOS server will run. |
| `FLOWOS_PORT` | Integer | `7860` | The port on which the FlowOS server runs. The server automatically selects a free port if the specified port is in use. |
| `FLOWOS_BACKEND_ONLY` | Boolean | `False` | Run only the FlowOS backend service (no frontend). |
| `FLOWOS_DEV` | Boolean | `False` | Whether to run FlowOS in development mode (may contain bugs). |
| `FLOWOS_OPEN_BROWSER` | Boolean | `False` | Open the system web browser on startup. |
| `FLOWOS_HEALTH_CHECK_MAX_RETRIES` | Integer | `5` | Set the maximum number of retries for FlowOS's server status health checks. |
| `FLOWOS_WORKERS` | Integer | `1` | Number of worker processes. See [Deploy FlowOS with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `FLOWOS_WORKER_TIMEOUT` | Integer | `300` | Worker timeout in seconds. See [Deploy FlowOS with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `FLOWOS_GUNICORN_PRELOAD` | Boolean | `False` | Enables Gunicorn `preload_app`. Non-Windows only. See [Deploy FlowOS with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `FLOWOS_JOB_QUEUE_TYPE` | String | `asyncio` | Job queue backend. Use `redis` for multi-worker deployments. See [Deploy FlowOS with multiple workers](./deployment-multi-worker#configuration-reference). |
| `FLOWOS_SSL_CERT_FILE` | String | Not set | Path to the SSL certificate file for enabling HTTPS on the FlowOS web server. This is separate from [database SSL connections](/configuration-custom-database#connect-flowos-to-a-local-postgresql-database). |
| `FLOWOS_SSL_KEY_FILE` | String | Not set | Path to the SSL key file for enabling HTTPS on the FlowOS web server. This is separate from [database SSL connections](/configuration-custom-database#connect-flowos-to-a-local-postgresql-database). |
| `FLOWOS_DEACTIVATE_TRACING` | Boolean | `False` | Deactivate tracing functionality. |
| `FLOWOS_CELERY_ENABLED` | Boolean | `False` | Enable Celery for distributed task processing. |
| `FLOWOS_ALEMBIC_LOG_TO_STDOUT` | Boolean | `False` | Whether to log Alembic database migration output to stdout instead of a log file. If `true`, Alembic logs to `stdout` and the default log file is ignored. |

| `FLOWOS_LOAD_FLOWS_PATH` | String | Not set | Path to a directory containing flow JSON files to be loaded on startup. Typically used when creating a Docker image with prepackaged flows. Requires `FLOWOS_AUTO_LOGIN=True`. |
| `FLOWOS_LOAD_FLOWS_OVERWRITE_ON_NAME_MATCH` | Boolean | `False` | When a flow file in `FLOWOS_LOAD_FLOWS_PATH` shares a name with an existing DB row but has a different `id`, controls whether to overwrite the existing row. `False` (default) skips with a warning so UI edits are preserved on restart when file UUIDs regenerate. | `FLOWOS_CREATE_STARTER_PROJECTS` | Boolean | `True` | Whether to create templates during initialization. If `false`, FlowOS doesn't create templates, and `FLOWOS_UPDATE_STARTER_PROJECTS` is treated as `false`. |
| `FLOWOS_UPDATE_STARTER_PROJECTS` | Boolean | `True` | Whether to update templates with the latest component versions when initializing after an upgrade. |
| `FLOWOS_LAZY_LOAD_COMPONENTS` | Boolean | `False` | If `true`, FlowOS only partially loads components at startup and fully loads them on demand. This significantly reduces startup time but can cause a slight delay when a component is first used. |
| `FLOWOS_EVENT_DELIVERY` | String | `streaming` | How to deliver build events to the frontend: `polling`, `streaming` or `direct`. |
| `FLOWOS_FRONTEND_PATH` | String | `./frontend` | Path to the frontend directory containing build files. For development purposes only when you need to serve specific frontend code. |
| `FLOWOS_FS_TOOL_BASE_DIR` | String | `~/.flowos/fs_tool/fs_sandbox` | Base directory for the [**File System** component](../Components/file-system.mdx) sandbox. All agent file operations are confined to this directory. |
| `FLOWOS_MAX_ITEMS_LENGTH` | Integer | `100` | Maximum number of items to store and display in the visual editor. Lists longer than this will be truncated when displayed in the visual editor. Doesn't affect outputs or data passed between components. |
| `FLOWOS_MAX_TEXT_LENGTH` | Integer | `1000` | Maximum number of characters to store and display in the visual editor. Responses longer than this will be truncated when displayed in the visual editor. Doesn't truncate outputs or responses passed between components. |
| `FLOWOS_MAX_TRANSACTIONS_TO_KEEP` | Integer | `3000` | Maximum number of flow transaction events to keep in the database. |
| `FLOWOS_MAX_VERTEX_BUILDS_TO_KEEP` | Integer | `3000` | Maximum number of vertex builds to keep in the database. Relates to [Playground](/concepts-playground) functionality. |
| `FLOWOS_MAX_VERTEX_BUILDS_PER_VERTEX` | Integer | `2` | Maximum number of builds to keep per vertex. Older builds are deleted. Relates to [Playground](/concepts-playground) functionality. |
| `FLOWOS_PUBLIC_FLOW_CLEANUP_INTERVAL` | Integer | `3600` | The interval in seconds at which data for [shared Playground](/concepts-playground#share-a-flows-playground) flows are cleaned up. Default: 3600 seconds (1 hour). Minimum: 600 seconds (10 minutes). |
| `FLOWOS_PUBLIC_FLOW_EXPIRATION` | Integer | `86400` | The time in seconds after which a [shared Playground](/concepts-playground#share-a-flows-playground) flow is considered expired and eligible for cleanup. Default: 86400 seconds (24 hours). Minimum: 600 seconds (10 minutes). |

### Hide UI elements with embedded mode {#embedded-mode}

When you embed the FlowOS visual editor in another application, such as an iframe within a host portal, you can hide UI elements that are usually visible in the visual editor.

The embedded mode environment variables control which UI elements appear in the visual editor.
Embedded mode controls UI visibility only, and does not block API endpoints or deploy FlowOS.

Embedded mode is distinct from the [embedded chat widget](/concepts-publish#embedded-chat-widget), which embeds a single flow's chat UI in a website.

When `FLOWOS_EMBEDDED_MODE=true`, FlowOS hides the following buttons in the UI:

* **Logout**
* **New project**
* **New flow**
* **Starter projects**

You can hide individual elements without enabling the umbrella flag.

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `FLOWOS_EMBEDDED_MODE` | Boolean | `False` | Umbrella flag for embedded or iframe deployments. When `true`, hides standalone UI elements: logout, new project, new flow, and starter projects. Individual hide flags can also be set without enabling this flag. |
| `FLOWOS_HIDE_LOGOUT_BUTTON` | Boolean | `False` | If `true`, hides the logout button in the account menu. Automatically enabled when `FLOWOS_EMBEDDED_MODE=true`. |
| `FLOWOS_HIDE_NEW_PROJECT_BUTTON` | Boolean | `False` | If `true`, hides the new project/folder button in the sidebar. Automatically enabled when `FLOWOS_EMBEDDED_MODE=true`. |
| `FLOWOS_HIDE_NEW_FLOW_BUTTON` | Boolean | `False` | If `true`, hides the new flow button in the header. Automatically enabled when `FLOWOS_EMBEDDED_MODE=true`. |
| `FLOWOS_HIDE_STARTER_PROJECTS` | Boolean | `False` | If `true`, hides the starter projects tab in the templates modal. Does not affect database seeding of starter projects. Automatically enabled when `FLOWOS_EMBEDDED_MODE=true`. |
| `FLOWOS_HIDE_GETTING_STARTED_PROGRESS` | Boolean | `False` | If `true`, hides the getting-started onboarding progress UI. Not automatically enabled when `FLOWOS_EMBEDDED_MODE=true`. |
